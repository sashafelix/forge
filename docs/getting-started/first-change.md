# Run a supervised first change

This recipe creates a disposable Python repository, then supplies it to the
Forge orchestrator through a compatible execution host. Setup and structural
examples are exercised in CI. The model-backed part requires your installed,
authenticated host; no completed provider-backed transcript is bundled.

This recipe uses the Claude Code adapter. For operator-selected HTTP models,
controlled Docker commands and host-managed recovery, use the separate
[governed host walkthrough](../governed-host.md).

## 1. Create the baseline

From the Forge checkout:

```bash
python3 examples/first-change/create_demo.py
```

Expected: one passing baseline test, followed by JSON containing absolute
paths, a unique `story_id` and the pinned `base_revision`. The same JSON is saved
as `demo.json` in the printed `demo_root`. No model runs or governed artifacts
are generated by setup. `--output /absolute/path/to/new-demo` is optional and
refuses an existing directory.

The target has `greeting.py` and `test_greeting.py`. Initially `greet()` returns
`Hello!`; supplied names are ignored. Operator inputs request named greetings,
whitespace trimming, rejection of blank names and preservation of the default.
The accompanying facts describe a bounded, low-risk, single-module change.

Inspect those inputs, then check classification using the printed facts path:

```bash
python3 scripts/resolve-profile.py /absolute/path/from/demo/facts.json
```

Expected: `selected_profile` is `small`, with no required specialists or manual
checkpoints. A different task needs independently reviewed facts; do not copy
this classification to a real project.

## 2. Prepare an execution host

The supplied Claude Code layout is one adapter. Follow its [official setup](https://code.claude.com/docs/en/quickstart)
or your organisation's approved distribution, then confirm:

```bash
claude --version
claude auth status
python3 scripts/sync-agent-adapters.py
```

If authentication is missing, use `claude auth login`. Model selection is your
host's configuration; this recipe prescribes no particular model ID. Other
hosts must implement the [portable adapter requirements](../model-portability.md).

Review role permissions before execution. This repository supplies prompts,
not an OS sandbox or a complete role-specific tool policy. The host must supply
real command execution, scoped writes and separate stage invocations. If it
cannot satisfy a required boundary, stop the pilot and record the limitation.

## 3. Launch from the Forge checkout

Use `target_repo` and `input_dir` from `demo.json`:

```bash
claude --agent ai-pipeline-rgr-orchestrator \
  --add-dir "/absolute/path/from/demo/target" "/absolute/path/from/demo/inputs"
```

The orchestrator is the main session. Forge's contracts/scripts and project
agent definitions resolve from this checkout; the target is a separate Git
repository. `--add-dir` exposes directories to the host. It does not enforce
read-only access to inputs or stage-specific write scope. Do not bypass the
host's permission prompts. Official [CLI reference](https://code.claude.com/docs/en/cli-reference)
and [agent reference](https://code.claude.com/docs/en/sub-agents) were checked on
2026-10-06; record your actual runtime version.

Supply this operator request, replacing the uppercase placeholders with the
values printed by setup:

```text
Run Forge's nine-stage small-change workflow for STORY_ID.
Forge tooling root: FORGE_ROOT
Target Git repository: TARGET_REPO
Pinned baseline revision: BASE_REVISION
Immutable operator plan input: PLAN_INPUT
Immutable operator classification facts: FACTS_FILE
Run evidence directory: RUN_DIR

Validate the pack and resolve the supplied facts before implementation. Use
the operator-selected routing policy and only runtime targets independently
established as available by this host. For this Claude Code pilot use the
shipped compatibility routing with frontier-default; do not declare local
HTTP targets available unless a governed adapter is actually installed.

Create an isolated story worktree in TARGET_REPO/.agent-runs/STORY_ID from the
pinned baseline. Keep the baseline checkout and operator input bytes unchanged.
Snapshot the inputs into RUN_DIR. Write run evidence there; do not modify Forge
contracts, prompts, validators or other source files. Delegate stages through
their canonical roles, keep VERIFY a distinct invocation, and validate actual
outputs before advancing. Preserve real command exits and logs. Halt on missing
host capabilities, deterministic failure or invalid evidence. Preserve failed
evidence; do not fabricate success or silently repeat completed stages.

Return the story worktree path, evidence path, checks run and unresolved gaps
for human review. Do not merge or deploy.
```

Direct `plan-input.md` is supported, so optional intake is unnecessary for this
fully specified request. The host must bind the supplied operator policy;
target-repository files cannot change runtime, roles or risk authority.

## 4. Review the result

From Forge, replace the run path with the printed `run_dir`:

```bash
python3 scripts/validate-run-bundle.py /absolute/path/from/demo/run
python3 scripts/validate-run-governance.py /absolute/path/from/demo/run
```

Inspect `brainstorm.json`, the locked plan, RED's intended failures, GREEN's
passing output, VERIFY's independent command output and the convergence report.
Every requested behaviour must map to real test evidence. An incomplete or
failed run is expected to fail completed-bundle validation; use the
[recovery guide](../operations.md) instead of editing it into a passing bundle.

Review the returned worktree and rerun its tests independently:

```bash
git -C "/absolute/path/from/demo/target" worktree list
git -C "/absolute/path/to/story-worktree" status --short
git -C "/absolute/path/to/story-worktree" diff BASE_REVISION
cd "/absolute/path/to/story-worktree"
python3 -m unittest -v
```

Replace `BASE_REVISION` with the pinned SHA. Git diff omits untracked files;
inspect them from the status output too. Check that no writes escaped the
locked scope and that the input snapshots match the operator originals.
Record the Forge SHA, host version, selected model reference, actual outcome
and any human corrections. Only the operator decides whether to retain or
publish the result. See [operations](../operations.md) for worktree cleanup.
